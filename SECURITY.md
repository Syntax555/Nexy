# Security policy

## Supported version

Security fixes target the current `main` branch and the currently deployed
GitHub Pages site. Older commits and local forks are not maintained releases.

## Report a vulnerability

Prefer a private report through the repository's **Security** tab and private
vulnerability reporting. Include:

- the affected URL, file, or workflow;
- the impact and conditions required to reproduce it;
- minimal reproduction steps or a proof of concept; and
- any suggested mitigation.

If private vulnerability reporting is unavailable, open a public issue that
only asks the maintainer for a private contact route. Do not include exploit
details, credentials, tokens, personal information, or other sensitive data in
that issue.

Relevant reports include cross-site scripting, unsafe path handling in the
content or image pipeline, dependency or CI compromise, and exposure of
sensitive information. Copyright, trademark, attribution, and artwork-removal
concerns are not security vulnerabilities; use the rights-holder request form
linked from the README.

Please allow the maintainer time to confirm the issue and coordinate a fix
before public disclosure.
